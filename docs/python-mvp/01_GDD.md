# 01 · Game Design Specification (GDD)

**Проект:** Python-режим «Профик Арены»
**Статус:** Production-ready spec для MVP вертикального среза
**Версия:** 1.0

> Этот документ отвечает на вопрос **«что за игра»**.
> Технику см. в `02_TDD.md`, арт в `03_ArtBible.md`, уровни в `04_LevelDesignBible.md`.

---

## 1. Vision

Одна фраза для всей команды:

> **Игра, в которой ребёнок учится Python, но чувствует, что проходит приключение.**

Слоган для маркетинга:

> **«Твой код оживает на экране.»**

Уникальный элемент, отличающий от всего рынка (Codecombat, CodeMonkey, Grasshopper):

> **«Живой Python» — код игрока в реальном времени превращается в действия Профика в мире.**

Это ядро игры. Всё остальное существует ради усиления этого чувства.

---

## 2. Player Fantasy

Что чувствует игрок в разные моменты:

| Момент | Чувство |
|---|---|
| Первый вход | «О, кот. Забавно.» |
| Первый `print` | «Так, я написал слово и оно появилось на экране.» |
| Первый цикл | «Стой. Я написал 3 символа, а он прыгнул 5 раз?» |
| Первая ошибка | «Профик замер, посмотрел на меня. Не осудил.» |
| Первое раскрытие Осколка | «У меня теперь есть кусок мира. Я хочу ещё.» |
| Первое оживление мира | «Я это сделал.» |
| Друг спрашивает «что играешь» | «Сложно объяснить. Это как… программирование, но не.» |

**Anti-fantasy** (чего игрок НЕ должен чувствовать):
- «Меня учат.»
- «Это домашка.»
- «Я тупой, не понял.»
- «Скучно, дай кнопку "пропустить".»

## 3. Core Loop

```
Заходит →
Видит карту (шёпот, дальние точки, оживший пройденный мир) →
Тапает Мир →
Читает микро-сцену Профика (1-2 реплики) →
Играет уровень (30-90 сек) →
Собирает код визуально или тапает варианты →
Тапает ▶ показать →
Смотрит анимацию выполнения →
Получает XP + звук + хаптик →
Идёт на следующий уровень →
... 10 уровней ... →
Раскрытие Осколка (3D-карточка, фанфара) →
Оживление мира на карте →
Новая способность Профика →
Возвращается на карту → видит что мир изменился → выходит с улыбкой
```

**Целевая длительность одной сессии:** 5-8 минут.
**Целевая длительность прохождения среза:** 25-40 минут.
**Целевая частота возврата:** через 1-3 дня.

## 4. Learning Beats (эмоциональная архитектура)

Принцип от Nintendo: **уровни строятся не по возрастанию сложности, а по эмоциональной волне.**

Beat = одна эмоция игрока за уровень. 5 базовых бита:

| Beat | Эмоция | Функция уровня |
|---|---|---|
| **Discovery** | «Ого, а такое можно?» | Показать новый приём |
| **Success** | «У меня получилось!» | Закрепить, дать ощущение мастерства |
| **Confusion** | «Стой. Почему так?» | Контролируемая ошибка |
| **Insight** | «А-а, понял!» | Разрешить путаницу, показать логику |
| **Consolidation** | «Теперь я могу.» | Комбо приёмов, применение |

Плюс два специальных:

| Beat | Эмоция | Функция |
|---|---|---|
| **Mini-boss** | «Соберись.» | Проверка комбо всех приёмов уровня |
| **Payoff** | «Смотри что я сделал!» | Финал мира с визуальным событием |

Раскладка для среза «Дюны Возврата» — см. `04_LevelDesignBible.md`, раздел «Pacing curve».

## 5. Педагогическая таблица «Почему именно эта визуализация»

Правило: **у каждой визуализации должна быть педагогическая причина.**
Если визуализация «просто красивая», но не проясняет концепцию — убираем.

### Что визуализируем в срезе

| Python-концепция | Визуализация | Педагогическая причина |
|---|---|---|
| `print("текст")` | Профик произносит облако с текстом | Показывает, что print = «сказать наружу» |
| Переменная `x = 5` | Коробка с надписью «x», внутри цифра 5 | Показывает: у имени есть содержимое, оно может меняться |
| Целое число | Цифра на плоском жетоне | Атомарность (не разбивается) |
| Строка `"abc"` | Лента из букв-плиток | Последовательность символов |
| Список `[10, 20, 30]` | Поезд из вагонов с номерами | Порядок + возможность доступа по индексу |
| `range(n)` | Дорожка из n плиток | Конечность диапазона наглядна |
| `range(start, stop)` | Дорожка с явным началом и концом | Правая граница НЕ входит — на плитке видно |
| `range(a, b, step)` | Плитки через промежуток | Шаг = визуальный интервал |
| `for i in range(n)` | Профик прыгает по плиткам, `i` меняется в коробке | Повторение действия с переменной-счётчиком |
| `for x in list` | Профик идёт по вагонам поезда | Итерация по элементам |
| Индекс `a[0]` | Указатель на вагон номер 0 | Прямой доступ |
| Ошибка (IndexError и т.п.) | Профик врезается, экран дрожит, «пффф» | Ошибка = событие, а не наказание |

### Что НЕ визуализируем (за пределами среза, но принцип на будущее)

| Концепция | Причина не-визуализации |
|---|---|
| `lambda` | Абстракция без явного мирового аналога — цирк, а не ясность |
| `map`, `filter`, `zip` | Функциональные примитивы — лучше показывать через явный цикл |
| Декораторы | Слишком мета — путают, а не проясняют |
| Type hints | Служебная разметка — визуализация утяжеляет |
| Импорты | Просто текст, ничего не оживляет |

Эти вещи показываем через **обычный текст в редакторе кода** — без анимации, без Профика.

## 6. Демо-мир (Пролог)

**Добавлено по требованию эксперта.** Три минуты перед Миром «Дюны Возврата».

**Цель пролога:** дать фундамент до цикла — команда → последовательность → повторение.

Пролог состоит из 4 микро-сцен, каждая 30-45 секунд:

| Сцена | Что происходит | Учит |
|---|---|---|
| **1. Первое слово** | Профик молчит. Игрок собирает `print("Привет")`. Тап ▶ — Профик говорит облаком «Привет». | print = сказать |
| **2. Коробка** | Появляется пустая коробка «имя». Игрок пишет `имя = "Игорь"`. Профик читает и говорит: «Привет, Игорь.» | переменная |
| **3. Две команды** | Игрок пишет две команды подряд. Профик выполняет их по очереди. | последовательность |
| **4. Пять раз** | «Профик, скажи "ура" 5 раз.» Игрок пишет по-старому `print("ура"); print("ура")...` — устаёт. Появляется подсказка: «есть короче». Одна кнопка `for i in range(5)`. Тап ▶. Магия. | зачем нужен цикл |

**После сцены 4** — карта. Дюны Возврата уже открыты. Игрок хочет туда, потому что только что сам почувствовал: «а, циклы — это круто».

Пролог **не пропускаемый первый раз, всегда пропускаемый после.** Хранится в CloudStorage флаг `python.prologueCompleted`.

## 7. Sandbox (Песочница после мира)

**Добавлено по требованию эксперта.** Появляется в конце каждого мира — включая срез.

**Цель:** дать ребёнку исследовательское поведение без страха ошибки.

### Правила

- Нет цели.
- Нет XP.
- Нет ошибок (любая ошибка = «Профик пожал плечами и всё»).
- Нет таймера.
- Есть Профик и все приёмы, изученные в мире.

### Интерфейс

Пустая пустыня. Внизу экрана — панель со всеми приёмами мира (в срезе: `range`, `for`, `.hop()`, `.say()`, переменные). Игрок таскает их, строит код, тапает ▶, смотрит что получится.

Кнопка «поделиться» — сохраняет короткий gif через canvas.captureStream, чтобы отправить другу.

### Триггер выхода

Единственная кнопка «на карту». Никакого «выполните задачу для выхода».

## 8. Мета-прогрессия (что копится между сессиями)

Три параллельных прогресса:

### 8.1. Осколки (album)
- 15 карточек = 15 миров.
- Каждая — 3D-открытка с иллюстрацией и одной строкой лора.
- Раскрытие — событие с фанфарой (см. Art Bible, раздел «Ceremonial moments»).

### 8.2. Оживление карты
- До прохождения мир — плоский силуэт.
- После — оживает: движение, звук окружения, следы Профика.
- Ощущение личного вклада: «я это разбудил».

### 8.3. Способности Профика
- После каждого мира — одна новая способность.
- Не открывают новый функционал, а меняют ощущение.
- Всегда косметика + маленький игровой эффект (быстрее анимация, красивее переход).

Полный каталог (для будущих миров):

| После мира | Способность | Эффект |
|---|---|---|
| 1. Порт Забытых Слов (print) | Голос | Реплики Профика теперь озвучены |
| 2. Хранилище Имён (переменные) | Метки | Профик может подписывать предметы |
| **3. Дюны Возврата (циклы)** | **Бег** | **Быстрее анимация движения (в срезе)** |
| 4. Лабиринт Условий (if) | Чутьё | Подсвечивает правильный путь на 0.5с |
| 5. Библиотека Строк (str) | Шёпот букв | Может произносить строки по буквам |
| 6. Мастерская Функций (def) | Клон | Один раз может создать двойника |
| ... | | |

## 9. Профик с памятью

Профик — не помощник, не тьютор. **Он — сосед по игре.** Он замечает и комментирует.

### Черты характера

- Спокойный, чуть уставший.
- Не хвалит фальшиво.
- Может подколоть.
- Не осуждает ошибку.
- Иногда молчит (это тоже реплика).

### Триггеры и реплики (для среза)

10 базовых реплик — см. `Python_MVP_вертикальный_срез.md`, раздел 7. Полный каталог для полной игры — 60-80 реплик. Ведётся в отдельном файле `profik_lines.json` (создаётся в фазе продакшена).

### Правила подачи

- Не более 2 реплик подряд.
- Не чаще 1 реплики в 2 минуты игры.
- Никогда не блокирует ввод (реплика — облако сверху, игрок продолжает играть).
- Реплика может быть **молчанием** (Профик просто смотрит) — иногда это сильнее.

## 10. Финал полной игры (target state, не для среза)

Из v3 с правкой эксперта. Оставлено, чтобы команда видела куда движется проект.

1. Все 15 миров пройдены, карта оживает панорамой.
2. Профик садится рядом с игроком.
3. Открывается пустой `>>> _`.
4. Профик: «Теперь ты можешь писать свою историю.»
5. Игрок печатает: `print("Спасибо.")`
6. Консоль отвечает: `Спасибо.`
7. Профик улыбается. Кивает. Исчезает.
8. Титры (10 строк, ~30 секунд).

Никаких сертификатов, никаких фанфар. Тихое достоинство. **Финал должен ощущаться личным.**

## 11. Non-goals (что игра НЕ делает)

Явный список, чтобы не расползлось в продакшене:

- **Не является IDE.** Нет автодополнения, нет отладчика, нет реальной консоли (кроме финала).
- **Не покрывает всю Python.** Только то, что в ЕГЭ по информатике (см. `Готовимся к ЕГЭ на Python 2025.pdf`).
- **Не оценивает.** Нет A/B/C/двоек. Есть «прошёл / не прошёл / прошёл идеально».
- **Не соревновательная.** ProfikCup и рейтинг — в других режимах, Python отдельно.
- **Не для взрослых-новичков.** Целевая аудитория — 8-11 класс.
- **Не работает без интернета.** Требует Telegram Mini App runtime.
- **Не имеет монетизации.** Полностью бесплатно. Единственный «продукт» — подписка на канал `@profimatika_inf`.

## 12. Success Metrics (для теста среза)

Продублировано из брифа для полноты GDD:

| Метрика | Целевое значение |
|---|---|
| Проходят пролог | ≥ 90% |
| Проходят все 10 уровней Дюн в первый заход | ≥ 70% |
| Просят «а когда следующий мир?» | ≥ 60% |
| Оценка ≥ 8/10 после сессии | ≥ 50% |
| Нажимают ▶ показать хотя бы 2 раза за сессию | ≥ 80% |
| Заходят в Sandbox хотя бы раз | ≥ 40% |
| Приходят повторно в течение 3 дней | ≥ 30% |
| «Покажу другу» без наводки | ≥ 20% |

Метрика `▶ показать` — ключевая. Если ей не пользуются, идея «Живого Python» не работает, и надо чинить не уровни, а сам движок.

## 13. Открытые вопросы (для решения до старта арта и разработки)

Требуют ответа Product Owner (Игорь):

1. **Озвучка Профика:** только звуки-щелчки или реальный голосовой актёр? (влияет на бюджет и pipeline)
2. **Пол Профика:** он / она / без указания? (влияет на реплики и локализацию)
3. **Возраст фокус-группы:** 8-11 весь диапазон или сначала узко (например, 8 класс)?
4. **Ошибки в консоли:** русифицируем `IndexError` в текст «в поезде столько нет вагонов» или оставляем как в реальном Python?
5. **Финал среза:** после Sandbox сразу «пещеры откроются в следующем обновлении» или добавляем короткий эпилог с Профиком?

Ответы фиксируем прямо в этом документе, следующая версия — 1.1.
